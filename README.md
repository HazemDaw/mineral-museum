# Музей минералогии и петрографии — прототип сайта

Веб-прототип сайта музея кафедры геологии. Каждый физический образец в
экспозиции получает QR-код; студент сканирует его телефоном и попадает на
страницу минерала с фотографией, научным описанием и **интерактивной 3D-моделью
кристаллической структуры**.

Оформление сайта — светлая, официальная тема, перекликающаяся со стилем
[amursu.ru](https://www.amursu.ru/) (белый фон, тёмно-синий акцент, золотисто-
охристые данные), а не тёмная "стартап"-тема из самой первой версии
прототипа. Витрина образца и 3D-просмотрщик структуры намеренно оставлены
тёмными "как в настоящей музейной витрине" — это единственные тёмные области
на сайте.

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # укажите домен музея для QR-ссылок
npm run dev                  # http://localhost:3000
```

Продакшн-сборка: `npm run build && npm start`.

> **Про сборку без интернета:** `next/font` скачивает Google Fonts во время
> `next build`. Если вы собираете проект в изолированной сети без доступа к
> `fonts.googleapis.com`, сборка завершится ошибкой загрузки шрифта — это
> ограничение сети, а не ошибка кода. При обычном подключении к интернету
> всё работает без изменений.

## Структура проекта

```
app/
  page.tsx                 — главная страница (каталог)
  mineral/[slug]/page.tsx  — страница одного минерала (куда ведёт QR-код)
  admin/page.tsx           — черновая панель сотрудника музея
components/
  MineralCard, MineralCatalog, SearchBar   — каталог и поиск
  MineralInfo                              — научная карточка минерала
  CrystalViewer, UnitCell, AtomLegend       — интерактивная 3D-визуализация
  QRCode                                   — генерация и печать QR-кода
  AdminPanel                               — редактирование данных (демо-режим)
lib/
  types.ts           — модель данных (Mineral, CrystalStructure, ...)
  minerals-data.ts   — данные пяти демонстрационных минералов
  crystal-utils.ts    — кристаллографическая математика (см. ниже)
```

## От CIF-файла до 3D-модели: архитектура конвейера

`CrystalViewer` не рисует "куб вместо структуры" — он принимает объект
`CrystalStructure` (см. `lib/types.ts`) в формате, который однозначно
соответствует данным CIF-файла:

```ts
{
  mineralId: "aquamarine",
  crystalSystem: "hexagonal",
  spaceGroup: "P6/mcc",
  cell: { a, b, c, alpha, beta, gamma },   // как в CIF _cell_length_*, _cell_angle_*
  atoms: [{ element: "Si", fractional: [x, y, z] }, ...], // как _atom_site_fract_*
  bonds: [{ fromIndex, toIndex }]          // необязательно, иначе — эвристика по расстоянию
}
```

`lib/crystal-utils.ts` конвертирует дробные координаты в декартовы
(`cellToCartesianMatrix` + `buildLattice`), размножает ячейку N×N×N и
центрирует результат. **Это единственное место, которое нужно будет
доработать при подключении реального парсера CIF** — вместо того, чтобы
строить `CrystalStructure` вручную (как сейчас в `minerals-data.ts`), его
будет собирать функция `parseCIF(file): CrystalStructure`. Компоненты
`CrystalViewer`, `UnitCell`, `AtomLegend` не изменятся.

**Важно: все пять 3D-структур в этом прототипе — условные, не научные
данные.** Параметры элементарной ячейки для берилла и аквамарина взяты из
справочных значений (a≈9.21 Å, c≈9.19 Å), но расположение атомов внутри
ячейки упрощено для наглядности, а не взято из уточнённой структуры. Для
остальных трёх минералов (астрофиллит, лампрофиллит, эвдиалит) условны и
параметры ячейки, и расположение атомов — они лишь соответствуют типу
сингонии, чтобы решётка выглядела правдоподобно и по-разному для каждого
минерала. Каждая структура помечена `isPlaceholder: true` и текстом в поле
`source`, а в интерфейсе — меткой «Модель условна — требуется CIF». Это
нужно заменить реальными координатами из CIF-файлов до научной публикации
или официального использования этих моделей в учебных целях.

## Важное примечание по одному образцу

Этикетка одного из образцов в коллекции содержит формулировку
«Хризоберилл зелёный БЕРИЛЛ» — хризоберилл (BeAl₂O₄, ромбическая сингония) и
берилл (Be₃Al₂Si₆O₁₈, гексагональная сингония) — разные минералы. Поскольку
этикетка указывает «Гекс. синг.», для прототипа принят берилл, а карточка и
страница минерала помечены отметкой **«Требует подтверждения»** — научные
данные не подменяются без проверки кафедрой.

## QR-коды

Каждая страница минерала кодирует **только свою стабильную ссылку**
(`/mineral/<slug>`), не данные образца — это позволяет музею обновлять
информацию, не перепечатывая таблички. Кнопка «Печать QR» на странице
минерала открывает готовую для печати карточку с названием музея, именем
минерала и QR-кодом.

## База данных (следующий шаг)

`lib/minerals-data.ts` — это временный массив в памяти, повторяющий будущую
схему БД:

```
Mineral          — id, slug, nameRu, formula, crystalSystem, hardness, density,
                   color, description, specimenImage, cifFile, createdAt, updatedAt
CrystalStructure — mineralId, unitCell, atoms, bonds, symmetry
```

Подключение реальной БД (Postgres/Prisma и т.п.) — это замена функций
`getMineralBySlug` / `getAllSlugs` на запросы к базе; ни один компонент
интерфейса менять не придётся, так как все они уже работают через типы
из `lib/types.ts`.

## Панель администратора

`/admin` — черновой интерфейс редактирования данных без авторизации
(согласно техническому заданию для первого прототипа). Архитектура готова
для добавления авторизации и реального сохранения (POST/PATCH к API) на
следующем этапе — сейчас изменения живут только в состоянии страницы.

## Фотографии образцов

Прототип **не содержит фотографий образцов** — на сайтах со сторонними
фотографиями минералов часто неясны условия лицензирования, а копировать
чужие изображения в проект без проверки авторских прав нельзя. Вместо этого
каждая карточка/страница минерала показывает аккуратную сгенерированную
заглушку (`public/specimens/<slug>.svg`) и **автоматически** переключится на
настоящую фотографию, как только она появится:

1. Сфотографируйте физический образец из коллекции кафедры.
2. Сохраните файл как `public/specimens/<slug>.jpg` — имя файла для каждого
   минерала уже указано в `lib/minerals-data.ts` (`specimenImage`), например
   `public/specimens/astrofillit.jpg`.
3. Больше ничего менять не нужно — `SpecimenImage` (`components/SpecimenImage.tsx`)
   сам подхватит файл и покажет его вместо заглушки.

## Мобильный опыт

Каталог, страница минерала и 3D-просмотрщик мобильны по умолчанию:
крупные кнопки, поддержка касания и «pin-to-zoom» в `CrystalViewer`
(`OrbitControls` из `@react-three/drei`), отсутствие горизонтального
скролла, лёгкие SVG-изображения образцов вместо тяжёлых фотографий на
этапе прототипа.
